=== HUỚNG DẪN SỬ DỤNG API THÔNG BÁO (NOTIFICATIONS) ===

1. ĐỊNH NGHĨA KEY:
   - Base URL: http://localhost:5000/api/v1
   - Auth: Yêu cầu Header [Authorization: Bearer <access_token>] (Role Customer)

2. DANH SÁCH API:

   A. LẤY DANH SÁCH THÔNG BÁO
      - Endpoint: GET /notifications
      - Mô tả: Lấy 50 thông báo mới nhất của người dùng hiện tại, sắp xếp theo thời gian giảm dần.
      - Response (Dạng mảng):
        [
          {
            "_id": "69xxxxxxxx",
            "userId": "69xxxxxxxx",
            "title": "Tài xế đã nhận đơn",
            "message": "Tài xế Nguyễn Văn A đang trên đường đến điểm lấy hàng.",
            "type": "ORDER_STATUS",
            "isRead": false,
            "data": {
               "orderId": "69xxxxxxxx",
               "status": "ACCEPTED"
            },
            "createdAt": "2024-03-24T00:00:00.000Z",
            "updatedAt": "2024-03-24T00:00:00.000Z"
          }
        ]

   B. ĐÁNH DẤU ĐÃ ĐỌC
      - Endpoint: PUT /notifications/:id/read
      - Tham số: :id là ObjectID của thông báo
      - Response: { "success": true }

3. CÁC LOẠI THÔNG BÁO HỆ THỐNG TỰ TẠO:
   - "Tài xế đã nhận đơn": Sinh ra khi tài xế bấm Accept hoặc Admin gán tài xế.
   - "Tài xế đã lấy hàng": Sinh ra khi tài xế bấm Xác nhận lấy hàng.
   - "Giao hàng thành công": Sinh ra khi tài xế bấm Hoàn thành chuyến đi.

4. GHI CHÚ CHO FRONTEND:
   - Bạn nên polling API này mỗi 10-15 giây để cập nhật badge số lượng thông báo chưa đọc (nếu muốn).
   - Field `data.orderId` giúp bạn có thể code logic: khi user click vào thông báo, ứng dụng tự động nhảy vào chi tiết đơn hàng đó.
